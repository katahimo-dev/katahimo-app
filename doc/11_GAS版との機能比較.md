# 11. GAS版との機能比較

- 目的: GAS版(`gas-childcare-visit-app` と、それを支える夜間の GAS プロジェクト)ができたことを1つずつ挙げ、新アプリで
  どうなるか(同じ・良くなる・変わる・しない)を、コードを確かめて一覧にする。新アプリが GAS版の上位互換かどうかと、
  切替の日の運用に残っていることを判断する材料にする。
- 対象読者: 切替を判断する業務担当・管理者、運用者、レビューする人。

この資料は GAS版との**違い**を書く資料なので、GAS版の動きも書く。GAS版のコードは `legacy/gas-childcare-visit-app`
(サブモジュール)の `gas-childcare-visit-app/`(`Main.js`・`Auth.js`・`Schedule.js`・`RouteSearch.js`・`PastSchedule.js`・
`AttendanceCalc.js`・`CsvImport.js`・`GeminiReport.js`・`GoogleChat.js`・`Logging.js`・`Triggers.js`・`Bridge.js`・`index.html` ほか)と、
`C001-cutest-internal` の `01_GAS/gas-root-serach`(`main.js`・`lineworks.js`)・`01_GAS/gas-childcare-daily-report`。
新アプリの画面ごとの細かい決まりは [02_機能仕様.md](02_機能仕様.md)、業務・セキュリティに関わる意図的な違いの理由は
[02_機能仕様.md](02_機能仕様.md) 11章、画面の細かい違いは [`packages/web/README.md`](../packages/web/README.md)
「GAS版と意図的に変えているところ」。切替の手順は [09_移行計画.md](09_移行計画.md)。

## 判定の意味

| 判定 | 意味 |
| --- | --- |
| 同等 | 同じことが同じ結果でできる(文言・計算が同じ。計算は GAS版のコードを動かすテスト gasParity で一致を確かめているものがある) |
| 改善 | 同じことができ、さらに安全・正確・便利になっている(GAS版に無かったものを新アプリで足したものも含む) |
| 変更 | 目的は果たせるが、やり方・置き場所・範囲が変わる(理由を書く) |
| GAS版のみ | 新アプリではしない。**対応しない理由**(決定・代わりの手段)を書く |

## 1. ログイン・アカウント

| 機能 | GAS版 | 新アプリ | 判定 |
| --- | --- | --- | --- |
| ログイン | `verifyLogin`。スタッフ台帳の E列(メール)か M列(サブメール)とパスワード | `POST /api/auth/login`。メールかサブメールとパスワード、失敗の文言も同じ。法人ID(テナント)は URL・前回の値から決め、決まらないときだけ欄を出す | 同等 |
| 退職者のログイン | 退職日(H列)の当日以降は拒否 | 同じ(テナントの時刻帯の業務日)。退職日を入れた時点でそのスタッフの全セッションを失効 | 改善 |

| セッションの期限 | 7日(残り6日を切ると延長)。上限なし | 無操作7日(同じ延長)+ ログインから30日で必ず切れる | 改善 |

| パスワード変更 | `changePassword`。長さの決まりなし | 現在のパスワードが必要なのは同じ。8〜128文字。成功で入力欄を空にする | 変更(推測されにくく、ハッシュへの過大な入力を防ぐため長さを決めた) |
| 役割 | 台帳 K列の「管理者」フラグ(管理者/一般の2つ) | `staff` / `coordinator` / `admin` の3つ。コーディネーターは他のスタッフの予定・出勤簿・日報を扱えるが管理の画面は無い | 改善 |
| 初めてのパスワード | 管理者が台帳のパスワード列に書いて本人に伝える | 管理者が「✉️ パスワード設定の案内」をメールで送り、本人が番号で設定する(管理者はパスワードを知らない) | 改善 |
| スタッフの登録・編集・退職・削除 | 管理者がスタッフ台帳のシートを直接編集 | 🛠 管理 →「スタッフ」(入力の検証・版による競合の検出・操作ログつき)。削除は記録の無いスタッフだけ(記録があれば退職日) | 改善(7章にも) |

### 13.2 上位互換の状況

- スタッフの毎日の仕事(ログイン・今日と明日の予定とルート・お客様の情報と記録・日報/事故報告/ヒヤリハットと AI の下書き・
  領収書・出勤簿の修正とカレンダーの反映・今月のまとめ)は、全て新アプリの画面でできる。計算(予定の分類・ルートのつなぎ方・
  出勤簿の数式・カレンダーの反映)は GAS版のコードを動かすテストで結果の一致を確かめている。
- 管理者が GAS版でスプレッドシート・エディタを使っていた作業(スタッフ台帳・AIプロンプト・操作ログ・初めてのパスワード・
  全員分の日報/事故報告の閲覧と書き出し)は、🛠 管理タブに移った。夜間の処理も全て新アプリのジョブに移る。
- 「GAS版のみ」の8件は、どれも業務担当の決定か GAS 側の事情によるもの: シートを自由に編集できるデータ源にしない
  (シートでの反映・顧客の修正・日報の修正と削除・前月以前の修正)、画面を開いたときの顧客CSVの取込をしない、
  CRM シートに頼る「訪問時お願い」、停止済みの Google Chat の DM、LINE WORKS の DM の材料だった「ルート集計」シート。
- **ミラー(シートへの書き写し)を止める前に要るもの**: 領収書の画像の一覧(出勤簿タブの「🧾 領収書」。02 7.1)、全員分の日報・
  事故報告の一覧・書き出し(🛠 管理 →「📋 報告一覧」。02 10.2)、出勤簿のファイルの代わり(今月のまとめの「Excelで保存」。02 8.6)。
  3つとも実装済みで、機能の面では未実装のものは残っていない(止める前の確かめ方は 09 2.2)。
- 以上から、ミラーを続ける前提でも止める前提でも、GAS版でできたことは新アプリで全てできる(やり方が変わるものと、決定でしないものを
  除く)。ミラーを止めるかどうかは機能ではなく運用で決められる(GAS版の画面・他の GAS プロジェクト・人がまだシートを読むか)。
