# 09. 移行計画(GAS版 → 新版)

- 目的: 稼働中の GAS版(`gas-childcare-visit-app`)から新版(katahimo-app)へ、業務を止めずに切り替える手順・確認・戻し方を決める。
- 対象読者: 切替を行う運用者、業務担当(スタッフへの案内・並行稼働の判断)。

GAS 側の変更は `katahimo-dev/gas-childcare-visit-app` リポジトリで行う(このリポジトリの `legacy/` は読み取り専用)。
本番の構築は [07_インフラ・運用.md](07_インフラ・運用.md) 3章、GAS のプロジェクトとトリガーの一覧は [01_システム概要.md](01_システム概要.md) 2章。

## 1. 全体の流れ

```mermaid
flowchart LR
  a[1 準備<br/>本番の構築・取込・共有] --> b[2 並行稼働<br/>新版を試す・GAS版が正]
  b --> c[3 切替日<br/>GAS のトリガーを止め<br/>新版のジョブを動かす]
  c --> d[4 切替後の確認<br/>翌朝・1週間]
  d --> e[5 後片付け<br/>ミラー・Bridge・残りのトリガー]
  c -. 問題があれば .-> r[戻す<br/>6章]
```

| 段階 | 正のデータ | 夜間の反映・顧客CSV の取込 | スタッフが使う画面 |
| --- | --- | --- | --- |
| 準備・並行稼働 | GAS版(スプレッドシート) | GAS版のトリガー | GAS版(新版は一部の人が試す) |
| 切替後 | 新版(PostgreSQL) | 新版のジョブ(22:00 / 03:00 JST。翌日の予定のお知らせは 19:00) | 新版。ミラーを使うなら GAS版の画面・他の GAS プロジェクトもシートを読める |

### 2.2 ミラー(スプレッドシートへの書き込み)を続けるか

切替後も GAS版の画面・他の GAS プロジェクト(`gas-root-serach` 等)・人がスプレッドシートを読むなら、ミラーを続ける。

- [ ] 続ける場合: GAS版に **Bridge.js Ver. 1.1.38 以降** をデプロイした(それより前は事故報告の列がずれ、領収書の再送が二重になる。
      05 9章)。`gas_bridge_url`・`gas-bridge-secret`(GAS版の `BRIDGE_API_SECRET`)・`gas_bridge_tenant`(この GAS版を使っている
      テナントの slug)・`mirror_to_google_sheets = true` を設定した。ミラーされるのは `gas_bridge_tenant` のテナントの記録だけ
      (2つ目のテナントを入れても、その記録はこのスプレッドシートに書かれない。05 2.1)。
- [ ] ミラーを続ける間(と `SCHEDULE_PROVIDER=gas_bridge` を使う間)は GAS版の Web App を公開したままにする。
      `SCHEDULE_PROVIDER=gas_bridge` の間、夜間のカレンダー反映・翌日の予定のお知らせは `gas_bridge_tenant` のテナントだけを処理する
      (他のテナントは飛ばして INFO `*.tenant_skipped`。05 3章)。
- [ ] ミラーを続ける間は、新しい年度・新しいスタッフの個別出勤簿(`<スタッフ名>_出勤簿_<年度>年度`)を今までどおり
      gas-childcare-daily-report で作る(無いとその出勤簿へのミラーが失敗し続け、`dead` になる)。スタッフ台帳のシートには新版から
      書き込まないため、GAS の他のプロジェクトがまだ台帳を読む間は、新版での登録・退職をシートにも手で入れる。
- [ ] ミラーを続ける場合: 領収書の「会社負担」の区分と取消は「領収書一覧」シートに写らない(シートの列が決まっているため。取消した
      領収書の行もシートには残る。05 9章)ことを、シートで領収書を集計・請求している人に伝え、お客様への請求・スタッフへの支払いの
      集計は新版の「🧾 領収書」の CSV(区分の列つき・取消済みを除く)か出勤簿の Excel(うち会社負担・お客様請求分)で行うことにした。
- ミラーを止める前に要る画面(シートで見ていた領収書の画像・全員分の日報/事故報告・出勤簿のファイルの代わり)は、3つとも新版にある
  ([11_GAS版との機能比較.md](11_GAS版との機能比較.md) 13.2)。止める前に、下の3項目をそれぞれ確かめる。
- [ ] 領収書の画像と一覧: 管理者が「領収書一覧」シートと Drive で見ていた領収書を、新版の出勤簿タブの「🧾 領収書」(今月のまとめの
      「🧾 領収書の一覧・画像を見る」も同じ画面)で見られることを、管理者とコーディネーターで確かめた(本人の分。管理者・コーディネーターは
      他のスタッフ・全員分と CSV。[02_機能仕様.md](02_機能仕様.md) 7.1)。試しに1か月分を「領収書一覧」シートと見比べ、件数・合計が
      合うことを確かめた(新版で取消した領収書はシートに残るため、その分を除いて見比べる)。
- [ ] 全員分の日報・事故報告: 新版の「🛠 管理」→「📋 報告一覧」で見られることを、管理者とコーディネーターで
      確かめた(期間・種類・スタッフ・お客様で絞れる。[02_機能仕様.md](02_機能仕様.md) 10.2)。シートを読んでいた人・作業(集計・
      転記など)には、報告一覧の「⬇ 日報のCSV」「⬇ 事故報告・ヒヤリハットのCSV」(シートと同じ列の順+最終更新)に切り替えてもらった。
      ミラーを止める日までにシートに入った分と、止めた後の分は、CSV の期間(366日まで)で書き出せる。
- [ ] 出勤簿のファイル(`<スタッフ名>_出勤簿_<年度>年度`)の代わり: 管理者が月末に今月のまとめの「⬇ 全員分をExcelで保存」で、
      その月の全員分(1人1シート、テンプレートと同じ列・計算式・領収書の集計と明細つき。02 8.6)を保存できることを確かめた
      (一度に100人まで。その月に在籍している管理者・コーディネーターも数える)。メールの添付・ダウンロードを保護ビューで開いても
      計算の列・合計が見えること(式の結果の値も書いてある)も確かめた。
      1人分・年度分(12シート)は各スタッフも保存できる。試しに1か月分を GAS版の出勤簿と見比べ、労働時間数・残業・距離・超過回数・
      訪問等回数・領収書月集計が合うことを確かめてから、ミラーと個別出勤簿の作成(gas-childcare-daily-report)をやめる。

### 2.3 当月の出勤簿を DB に揃える

出勤簿のミラーは、新版の書き込みで表示の変わった列だけをシートに書く(新版に無い値を空で上書きしない)。ただし新版の DB に当月の
手入力が無いまま動かし始めると、画面・月のまとめ・次のカレンダー反映は DB だけを見るため、GAS版で手入力した当月の値(天候・備考・
手で直した時刻等)が新版に出てこない。**切替の直前に**、各スタッフの個別出勤簿(`<スタッフ名>_出勤簿_<年度>年度`)の当月のシートを
CSV(「ファイル → ダウンロード → CSV」)に書き出して取り込む:

```bash
pnpm import:attendance -- <slug> <スタッフのログインメール> <CSV> [--year YYYY]
```

- 1日ずつ差分で書き(`entity_changes.change_source = 'import'`)、同じ内容の再実行は何も書かない。ミラーは積まない。
- 当月の編集期限は掛けない(締めた月は DB が拒否する)。手で変えた強調表示は CSV に無いため取り込まれない。
- 読めないセルはそのセルだけ飛ばして表示するので、画面で直す。
- 取込から切替までに GAS版で手入力した日は、切替後に取込をやり直すか画面で直す。

### 2.4 日報・事故報告・領収書を取り込む

GAS版の「日報」「事故報告」シートと「領収書一覧」、領収書の画像を、運用担当者の CLI が Google Sheets API・Drive API で直接読んで
新版に取り込む(読むだけ。GAS版のスプレッドシート・Drive には何も書かない。05 12章)。取り込んだ報告は「🛠 管理」→「📋 報告一覧」・
お客様の「これまでの記録」に、領収書は「🧾 領収書」・今月のまとめ・出勤簿の Excel に出る。

**読むもの(ID はコードに持たず、CLI の引数で渡す)**: GAS版の `Config.js`(`legacy/gas-childcare-visit-app/gas-childcare-visit-app/Config.js`
の「現行環境」の値。Apps Script の画面で直接書き換えられることがあるため、`ConfigInspect.js` の `inspectConfigIds()` で動いている値を
確かめる)の次の3つ。

| Config.js | 名前 | 使い方 |
| --- | --- | --- |
| `SPREADSHEET_ID` | 「顧客DB 日報 事故報告」(「日報」「事故報告」シート) | `import:legacy-reports` の `--spreadsheet` |
| `IMAGE_LOG_SS_ID` | 「領収書一覧」(先頭のシート) | `import:legacy-receipts` の `--spreadsheet` |
| `RECEIPT_FOLDER_ID` | 「領収書」フォルダ(画像) | 共有だけ(画像はシートの写真の列の URL のファイル ID で読む) |

**どの Google アカウントで読むか**(どちらか。CLI は Application Default Credentials(ADC)で認証する):

- **(A) 運用担当者本人の Google アカウント(共有は要らない)**: 3つを既に読めるアカウント(持ち主の `info@cutest.biz` 等)で ADC を作る。
  領収書の画像を GCS に書くため、そのアカウントに領収書バケットへの書き込みの権限(プロジェクトの Owner なら既にある)が要る。
  ```bash
  gcloud auth application-default login --scopes=openid,https://www.googleapis.com/auth/userinfo.email,https://www.googleapis.com/auth/cloud-platform,https://www.googleapis.com/auth/spreadsheets.readonly,https://www.googleapis.com/auth/drive.readonly
  gcloud auth application-default set-quota-project <PROJECT_ID>   # 割り当て・課金のプロジェクト(Sheets API を有効にしたもの)。または export GOOGLE_CLOUD_QUOTA_PROJECT=<PROJECT_ID>
  ```
  Google が gcloud の既定の OAuth クライアントでの Drive・Sheets のスコープの同意を止める(「このアプリはブロックされています」)ことがある。
  その場合は (B) を使うか、プロジェクトの OAuth クライアント(種類「デスクトップ アプリ」)の JSON を作って
  `gcloud auth application-default login --client-id-file=<JSON> --scopes=…` で作る。
- **(B) サービスアカウント `katahimo-api@<PROJECT_ID>.iam.gserviceaccount.com`**(`terraform output -json service_accounts | jq -r .api`。
  領収書バケットに書けるのは api のサービスアカウントだけのため、worker ではなく api に共有する): GAS版に **Ver. 1.1.39 以降**
  (`MigrationShare.js`)をデプロイし、Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」の `KATAHIMO_SERVICE_ACCOUNT_EMAIL` に
  このメールアドレスを入れ、**3つの持ち主のアカウント**で `shareMigrationSourcesWithServiceAccount()` を実行する(3つを閲覧者で共有。
  通知メールは送らない。何度実行してもよい)。`listMigrationSourceSharing()` で3つともこのメールアドレスが閲覧者に入ったことを確かめる。
  CLI は運用担当者の端末からそのサービスアカウントに成り代わって流す(サービスアカウントの鍵は作らない):
  ```bash
  gcloud iam service-accounts add-iam-policy-binding katahimo-api@<PROJECT_ID>.iam.gserviceaccount.com \
    --member=user:<運用担当者のメール> --role=roles/iam.serviceAccountTokenCreator      # 移行の間だけ。5.3 で外す
  gcloud auth application-default login --impersonate-service-account=katahimo-api@<PROJECT_ID>.iam.gserviceaccount.com
  ```

CLI の環境は 07 3.6 と同じ(Auth Proxy 経由の `DATABASE_URL` 等)に、領収書の画像の保存先 `STORAGE_PROVIDER=gcs`・
`GCS_BUCKET="$(terraform -chdir=infra/gcp output -raw receipts_bucket)"` を足す。担当はスタッフの氏名、お客様は RESERVA の顧客ID で探すため、
**スタッフ台帳と顧客CSV を先に取り込んでおく**(2.1)。

```bash
pnpm import:legacy-reports -- <slug> --spreadsheet '<SPREADSHEET_ID>' --dry-run      # 件数と行ごとの結果を確かめる
pnpm import:legacy-reports -- <slug> --spreadsheet '<SPREADSHEET_ID>'
pnpm import:legacy-receipts -- <slug> --spreadsheet '<IMAGE_LOG_SS_ID>' --month <切替の月 YYYY-MM> --dry-run
pnpm import:legacy-receipts -- <slug> --spreadsheet '<IMAGE_LOG_SS_ID>' --month <切替の月 YYYY-MM>
```

- [ ] 日報・事故報告は**全ての行**を取り込んだ。領収書は少なくとも**切替の月**を取り込んだ(前の月も要るなら `--month` を並べるか
      `--from YYYY-MM --to YYYY-MM`。領収書日時の月で選ぶ)。
- [ ] 誤り(`誤り`)の行が無い。出るのは行番号と理由のコードだけ(セルの値は出さない)。担当が見つからない(`staff_not_found`。
      退職したスタッフも探す。氏名の空白の違いは無視する)・お客様が見つからない(`customer_not_found`。報告には記録にお客様が要る)行は、
      スタッフ台帳・顧客CSV を取り込み直すかシートを直して流し直す。画像の誤り(`image_unsupported_type`: JPEG・PNG・WebP 以外。GAS版は
      画面で縮めた JPEG を保存していたため通常は出ない / `image_too_large`: 1.5MB 超 / `image_unavailable`: 削除済み・共有されていない)は、
      画面から登録し直す。誤りがあると CLI は終了コード 1。
- [ ] 取込を確かめた: 報告一覧(期間を GAS版の最初の日から、種類ごと)の件数が、シートの行数から見出し・空の行・`KatahimoReportId` のある行
      (本アプリからのミラー。取り込まない)・誤りの行を除いた数と合う。領収書は「🧾 領収書」の月の件数・合計が「領収書一覧」のその月
      (`KatahimoReceiptId` のある行を除く)と合う(本アプリで登録済みの同じ内容の領収書は `duplicate` として取り込まないため、その分を除く)。

取込の決まり:

- **何度流してもよい**。取り込んだ行は `legacy_imported_rows`(03)に残り、同じ行は2回作らない。行を指すキーは行番号・本文ではなく、
  GAS版の上書き保存で変わらない列(日報: 日時・担当・顧客ID・開始時刻 / 事故報告: 日時・担当・顧客ID / 領収書: 画像のファイル ID)。
  2回目以降は、シートで直された行(GAS版の上書き保存)だけ記録を直す(変更前は記録の履歴に残る)。確定済みの記録と、取込の後に新版で
  直された記録は直さない(`locked` / `edited_in_app`)。領収書は会計の記録なので直さない(`changed_in_sheet` を出すだけ)。
- 取り込んだ記録は提出済み。領収書は1行を1回の登録にし、会社負担ではない・取消していない領収書として作る(申し送りは GAS版が書いた行
  (登録の最初の1枚)にだけ付く)。画面の登録と同じ重複の判定を掛け、本アプリで登録済みの同じ内容は取り込まない。GAS版の同じ登録の中の
  同じ内容(往復の運賃等)は全て取り込む。
- スプレッドシートへのミラー・Google Chat・Web Push(PSI の知らせを含む)は積まない。操作ログに INFO/WARN `legacy_import.*.done`(件数だけ)、
  `import_runs` に `legacy_reports_sheet` / `legacy_receipts_sheet` の実行が残る。途中で失敗しても書き終えた分は残り、流し直せば続きから入る。
- GAS版で事故報告を上書き保存すると日時(保存の時刻)が変わるため、次の取込では別の行として入り、前に取り込んだ記録は
  「シートに無い取込済み」(記録の ID を表示)として知らせる(記録は消さない。報告一覧で確かめ、要らなければ運用で扱う)。日報の日付・開始時刻・
  担当・お客様を直した場合も同じ。
- ミラーが on の間に、取り込んだ記録を新版で直すと、ミラーはシートに**新しい行**(`KatahimoReportId` つき)を足す(元の GAS版の行は
  そのまま)。次の取込ではミラーの行は読まず、元の行は変わっていないので何もしない。

## 3. 並行稼働

- GAS版を正のまま、一部のスタッフ(管理者・コーディネーター)が新版で予定・お客様・日報・出勤簿を試す。

  ミラーが off ならスプレッドシートに出ない。

## 6. 戻し方

切替から問題が見つかった場合、GAS版に戻せるように**切替後しばらくは GAS版を消さない**。

| 状況 | 戻し方 |
| --- | --- |
| 新版のアプリの不具合(直前のデプロイが原因) | リビジョンを戻す(07 8.2)。GAS版には戻さない |
| 新版を使い続けられない(業務が止まる) | ① 新版の Scheduler を止める(`scheduler_paused = true`)② gas-childcare-visit-app の2つのトリガーを `enabled: true` に戻して `setupAllTriggers()` ③ スタッフに GAS版の URL を案内する |
| 切替後に新版だけに入ったデータ | ミラーが on なら、日報・事故報告・領収書・出勤簿の変わった列はスプレッドシートにも入っている。off なら、新版の画面(今月のまとめ等)から手でシートに写す。勤怠集計は GAS版の夜間反映が作り直す |

戻した後にもう一度切り替えるときは、2.3 の当月の出勤簿の取込からやり直す。
